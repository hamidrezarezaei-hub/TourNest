## ۲. نمای کلی معماری

### ۲.۱ سبک معماری

**Monolith + Layered Architecture**

- یک برنامهٔ واحد
- سه لایهٔ اصلی: Presentation, Business, Data
- مناسب تیم کوچک
- ساده برای شروع، قابل گسترش

### ۲.۲ دیاگرام لایه‌ها

```
┌─────────────────────────────────────────┐
│          Presentation Layer             │
│      Django Templates + Bootstrap       │
└─────────────────┬───────────────────────┘
                  │ Views / URLs
┌─────────────────▼───────────────────────┐
│            Business Layer               │
│              Django (Python)            │
└─────────────────┬───────────────────────┘
                  │ ORM
┌─────────────────▼───────────────────────┐
│              Data Layer                 │
│        SQLite / PostgreSQL              │
└─────────────────────────────────────────┘
```

### ۲.۳ جریان داده

۱. گردشگر در صفحهٔ تور، دکمهٔ «رزرو» را می‌زند.
۲. Django ورود کاربر و اعتبار فرم و ظرفیت تور را بررسی می‌کند.
۳. رزرو از طریق ORM در دیتابیس ذخیره می‌شود.
۴. کاربر کد پیگیری رزرو را می‌بیند.

## ۴. تصمیم‌های معماری (ADR)

### ADR-01: چرا Monolith؟

**تصمیم:** معماری Monolith

**دلیل:**

- تیم کوچک
- پیچیدگی کم
- سرعت توسعه بالاتر
- استقرار ساده

### ADR-02: چرا Django؟

**تصمیم:** Django برای کل برنامه

**دلیل:**

- احراز هویت و پنل ادمین آماده دارد
- یادگیری و توسعهٔ سریع
- امنیت پیش‌فرض خوب

### ADR-03: چرا PostgreSQL؟

**تصمیم:** PostgreSQL برای استقرار

**دلیل:**

- Relational و قدرتمند
- سازگار با Django
- رایگان و اوپن‌سورس

## ۵. مسیرها (URL)

### ۵.۱ مسیرهای عمومی

| Method | مسیر           | توضیح        |
|--------|----------------|--------------|
| GET    | /tours/        | فهرست تورها  |
| GET    | /tours/:id/    | جزئیات تور   |
| GET    | /tours/search/ | جست‌وجو      |

### ۵.۲ مسیرهای رزرو

| Method | مسیر               | توضیح       |
|--------|--------------------|-------------|
| POST   | /tours/:id/book/   | رزرو تور    |
| GET    | /bookings/         | رزروهای من  |
| POST   | /bookings/:id/pay/ | پرداخت      |

### ۵.۳ مسیرهای تورگردان و مدیر

| Method | مسیر                  | توضیح               |
|--------|-----------------------|---------------------|
| POST   | /guide/tours/         | ثبت تور             |
| PUT    | /guide/tours/:id/     | ویرایش تور          |
| DELETE | /guide/tours/:id/     | حذف تور             |
| GET    | /admin/               | پنل مدیریت (Django) |

## ۶. امنیت

### ۶.۱ احراز هویت

- **Django Auth** (Session)
- گذرواژه به‌صورت هش‌شده ذخیره می‌شود

### ۶.۲ مجوزدهی

- **Role-Based Access Control (RBAC)**
- نقش‌ها: Tourist, Guide, Admin

### ۶.۳ امنیت برنامه

- **HTTPS** اجباری
- **CSRF Protection** (پیش‌فرض Django)
- **Input Validation** با Django Forms

* * *

## ۷. مقیاس‌پذیری

### ۷.۱ محدودیت‌های فعلی

- Monolith → مقیاس‌پذیری محدود
- یک سرور → تک نقطهٔ شکست

### ۷.۲ مسیر رشد

1. فاز ۱ (MVP): Monolith + یک سرور
2. فاز ۲: انتقال به PostgreSQL
3. فاز ۳: Cache برای فهرست تورها
4. فاز ۴: جدا کردن سرویس‌های پرمصرف
